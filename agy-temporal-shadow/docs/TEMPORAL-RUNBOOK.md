# Local/staging run and rollback

Use the dedicated staging database, never a production URL. Runtime role must be NOSUPERUSER/NOBYPASSRLS. Keep auth out of source/Drive. No automated migration application to an existing environment is included.

1. Install dependencies from `pnpm-lock.yaml` (`pnpm install --frozen-lockfile`), then `pnpm build`. Only esbuild and protobufjs install scripts are allowlisted by pnpm workspace configuration.
2. Run official local CLI: `temporal server start-dev --ip 127.0.0.1 --port 7238 --ui-port 8238 --namespace agy-local --db-filename <private-staging-path>/temporal.sqlite --ui-disable-news-fetch`. Persist the SQLite file for server restart; memory-only dev server is insufficient. Namespace `agy-staging` is also accepted for approved local staging. Do not expose this dev service publicly.
3. On a **new disposable staging database**, apply existing migrations 001–008 in order and additive 009 with the migration owner. For an existing staging database already on 008, apply only 009 once with a backup/checkpoint. The owner must grant runtime role access to the three new tables/sequences as appropriate. Never rerun one-shot historical migrations.
4. Provision a separate ACTIVE project with `policies.temporalShadowOnly=true`, no native connectors and zero spend. Existing normal projects are rejected. Use existing scoped operator and reviewer identities externally via `AGY_IDENTITIES_JSON`.
5. Set `AGY_STAGE_ONLY=true`, `AGY_ORCHESTRATION_MODE=TEMPORAL_SHADOW`, `DATABASE_URL` from the secret store and the namespace/task queue from `config/temporal.env.example`. Start `pnpm temporal:worker` and `pnpm temporal:gateway`. Both bind/connect locally; gateway defaults to 127.0.0.1:8798.
6. Gateway contract: POST `/v1/agy/{action}`, Bearer auth, JSON `{ "mission": <Mission>, "verdict": <QA payload when applicable> }`. The same API is usable by any entrypoint; no chat/thread ID required. Fields are specified in `src/temporal/contracts.ts`. Operators: dispatch/reconcile/stop; reviewers: submit_qa; scoped read: bootstrap/current_state/task_status/get_run/active_missions. Example fixture is in `examples/temporal-shadow-mission.json`. `current_state` is project/domain bootstrap, while `get_run` returns domain ledger and Temporal state separately.
7. Submit independent QA only once ACK and result/evidence exist. Use the result's exact `evidence_refs`, current attempt, QA contract 1.1, PASS/FAIL. The reviewer comes from auth. FAIL requires `corrective_instruction`. Native chat plugin/MCP surface attachment is UNVERIFIED; an HTTP localhost PASS does not prove that Chat/Work can reach it.

Tests: set `AGY_TEST_DATABASE_URL` to the disposable test administrator URL and `AGY_TEST_TEMPORAL_ADDRESS=127.0.0.1:7238`, then `pnpm build` and `pnpm test`. Without both variables the new integration test skips and cannot earn durability PASS. Test process fixtures retain their isolated schemas as evidence. Test logs/history/receipts are in `runtime-evidence/`, outside the source manifest. Built-in historical tests clean up their own generated test schemas.

## Rollback without deleting history

Default config is `LEGACY`. To stop assigning new Temporal work, route callers back to the unchanged `src/server.ts` ProjectService `/jobs` API and set `AGY_ORCHESTRATION_MODE=LEGACY` for any gateway wrapper. The separate Temporal gateway/worker entrypoints require SHADOW and should not be started in LEGACY. No global production flag was changed.

For accepted shadow missions, use gateway `stop` (cooperative) or allow completion before stopping the worker. Stop retains any external/synthetic operation ID and marks blocked; it never blindly cancels a provider operation. Capture all pending/uncertain operation IDs, task IDs, leases and receipts. Never send those missions through legacy routing as new work. Restart the same Temporal service storage/namespace/task queue and resume the same run when reconciling.

Stop the local worker/gateway/dev server using their controlled lifecycle. Retain migration 009 and all evidence/SQLite files; rollback needs no DROP/DELETE and does not modify migrations 001–008. Check the existing legacy regression suite and compare pending records before any later production decision.

Lease recovery is tested with forced expiry after actual worker SIGKILL: it reconciles the same persisted ACK/operation/checkpoint, creates a new fence and claim attempt, and preserves the submission attempt. Missing/mismatched evidence or superseded ownership fails closed. Durability remains bounded by the configured mission deadlines; unlimited outage recovery is not claimed. Shadow task correction is fenced/deduplicated separately from native worker selection. Native executor, cloud staging, hosted uptime, caller chat closure and originating-chat ingestion remain separate acceptance gates.
