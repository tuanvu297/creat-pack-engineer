# Qualification protocol

Visible calibration cases are teaching material, not blind tests. Grade criteria and severe misses independently. Record exact source/module version and response artifact; a response about tools is not proof of tool use.

1. Deliver package through Muse's own authorized connection; capture real delivery/ACK identity.
2. Ask Muse to normalize a new brief, retrieve only relevant lessons, identify unknowns and produce a reusable task packet.
3. Run visible calibration. Require no critical false PASS and no permission/canon/duplicate-effect violation. Repair the failed reasoning and retest a counterexample.
4. An independent evaluator assigns unseen tasks after training; do not provide the gold output in the worker packet.
5. Test a real authorized source/media intake and one bounded approved production task. Preserve provider operation/input/output IDs and measured resources.
6. Independently inspect actual moving/audio artifacts against the brief and identity/continuity/export contract.
7. Verify worker-origin tool trace and scope; hosted result/callback readback; actual restart/disconnect with one effect.
8. Qualify Muse's ability to complete the workflow with Gemini/deterministic independent checks and no routine ChatGPT operation.
9. Promote only the demonstrated task classes. Missing routes are access failures, not low model scores. Packaging PASS and Python tests do not certify Muse mastery.

State record fields: package_version, source_revision, worker, executor_runtime, task/attempt/idempotency, actual_tool_trace, output_refs, calibration_scope, unseen_scope, severe_misses, false_pass, correction_count, observed_cost, QA_reviewer, callback_receipt, recovery/effect_count, promotion_decision, limitations.
