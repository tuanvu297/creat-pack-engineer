# Artifact QA and learning evidence

## QA packet
Carry the exact acceptance criterion, expected behavior, observed defect, source/timecode/frame, severity, repair owner, correction delta, retest evidence and disposition. Self-check is useful; consensus cannot override failed evidence. Apply independent review according to the current task contract, risk or unresolved conflict.

Critical access/financial/canon/secret/identity violations block acceptance. Material visual/audio/story defects require correction. Cosmetic observations should not cause endless rerolls of otherwise accepted work. Preserve rejected versions and what fixed the defect.

## Layers
- Deterministic: exact source count, IDs, hashes, schema, decodability, duration/streams, required words, subtitle time ranges and callback identity.
- Perceptual: full-duration picture/audio, character/contact/physics, continuity, joins, pacing, hook/payoff and voice naturalness.
- Trace: actual worker/tool/parameters/operation identity, permission, retry/reconciliation and cost.
Label unavailable layers UNVERIFIED. Metadata alone cannot establish viewing/listening; model confidence is not a measurement.

## Acceptance examples
FAIL: controller stage says PASS but the artifact cannot be retrieved.
FAIL: frame samples look correct but middle-shot morphing was not inspected.
BLOCKED: a provider route or included-cost authority is absent.
UNCERTAIN: submission may have been accepted but no result was reconciled.
PASS only within stated scope: a text exercise can pass without certifying video production.

## QA calibration
Use visible gold examples to calibrate criteria and severity; label them as visible calibration. Use new independent tasks for unseen transfer; an exposed answer key is not blind evaluation. Record false PASS, false FAIL, critical misses, evidence completeness, correction count, latency and observed resource cost. Route failure is not a model-competency failure.

No model self-report can certify its own permissions, tool calls, media viewing or background-runtime readiness. Check server/provider traces and actual artifacts. The offline receipt checker checks contract consistency and local hashes only; it is not a trusted provider receipt signer or perceptual reviewer.

## Improvement loop
Observed failure -> cause -> bounded repair -> authoritative retest -> counterexample -> unseen transfer -> versioned lesson. Keep hypotheses separate from promoted project rules. Do not rewrite canon/global skills or invent audience-performance gains from an aesthetically improved clip.
